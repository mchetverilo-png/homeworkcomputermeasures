| Broadcast-адреса          | `172.20.127.255`        | Адреса для надсилання даних усім пристроям цієї мережі                       |

## Завдання 2

Команда:

```bash
ip r
```

Результат:

```
default via 172.20.112.1 dev eth0 proto kernel onlink
172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1 linkdown
172.20.112.0/20 dev eth0 proto kernel scope link src 172.20.112.250
```

У результаті є слово `kernel`. Це означає, що маршрути додало ядро Linux

У моєму випадку WSL2 використовує `eth0` і `172.20.112.1`.

- `default via 172.20.112.1 dev eth0` - якщо для адреси немає окремого маршруту, дані надсилаються через `172.20.112.1`.
- `172.20.112.0/20 dev eth0` - маршрут усередині мережі до якої підключений `eth0`.
- `172.17.0.0/16 dev docker0` -  Docker неактивний

## Завдання 3

Команда:

```bash
curl ifconfig.io
```

Результат:

```
194.44.18.25
```

| Тип                 | Адреса           |
| ------------------- | ---------------- |
| Локальна (приватна) | `172.20.112.250` |
| Публічна            | `194.44.18.25`   |

Адреси різні, бо одна використовується всередині мережі, а інша - для зв’язку з інтернетом

`172.20.112.250` - локальна адреса WSL2. Вона належить до приватного діапазону `172.16.0.0/12` і використовується всередині мережі. `194.44.18.25` - публічна IPv4-адреса, яку вказано в результаті команди. IPv4-адреса складається з чотирьох чисел, розділених крапками

Коли пристрій виходить в інтернет,  шлюз зазвичай замінює його локальну адресу на публічну. Цей є NAT. Публічну адресу задає мережа або інтернет-провайдер; її не можна вибрати як хочеш
